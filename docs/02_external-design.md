# External Design

## 利用シーン

- コーディング作業中にエラーが発生した時

## CLIの起動方法

v1では、インストール済みのCLIコマンドとして起動できることを完了条件とする。

```bash
errorinsight
```

## 入力方法

ログをコピーし
クリップボードからログ文章を取得する

## 表示内容

- 抽出したエラー行
- 元ログ上の行番号
- エラー行ごとの原因候補
- 原因候補を推測できない場合の「不明」表示
- エラー行が見つからない場合のメッセージ

### 出力形式

抽出したエラー行ごとに、元ログ上の行番号、エラー行、原因候補を表示する。

```text
=== ErrorInsight Result ===

[1] Line 12
Error:
ValueError: invalid literal for int() with base 10: 'abc'

Cause Candidate:
数値に変換できない文字列を int() に渡している可能性があります。
```

```text

Error:

Cause Candidate:
指定したファイルパスが存在しない可能性があります。
```

=== ErrorInsight Result ===

エラーが見つかりませんでした。

エラー原因不明


## 正常系の動き

1. ユーザーがエラーログをクリップボードにコピーする
2. ユーザーがCLIで `errorinsight` を実行する
3. ErrorInsight がクリップボード内の複数行ログを取得する
4. ログを1行ずつ確認する
5. エラーらしいキーワードを含む行を抽出する
6. 抽出したエラー行ごとに原因候補を推測する
7. 抽出結果と原因候補をコンソールに表示する

## 異常系の動き

### クリップボードが空の場合

- ログが取得できないことを表示する
- 処理を終了する

### エラーらしい行が見つからない場合

- エラー行が見つからなかったことを表示する
- 処理を終了する

### 原因候補を推測できない場合

- エラー行は表示する
- 原因候補は「不明」として表示する

### クリップボードの取得に失敗した場合

- クリップボードを読み取れなかったことを表示する
- 処理を終了する

## ユーザー操作の流れ

1. 開発中にエラーが発生する
2. ターミナルやコンソールに表示されたログをコピーする
3. ターミナルで `errorinsight` を実行する
4. 抽出されたエラー行と原因候補を確認する
5. 表示された原因候補をもとに、修正箇所を調べる
