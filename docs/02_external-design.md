# External Design

## 利用シーン

- コーディング作業中にエラーが発生した時
- 長いログの中から読むべきエラー行を素早く見つけたい時

## CLIの起動方法

無料版では、インストール済みのCLIコマンドとして起動できることを目指す。

```bash
errorinsight
```

## 入力方法

1. ユーザーがターミナルやコンソールに表示されたログをコピーする
2. ErrorInsight がクリップボードからログ文字列を取得する

## 表示内容

- 抽出したエラー行
- 元ログ上の行番号
- エラー行が見つからない場合のメッセージ

### 出力形式

抽出したエラー行ごとに、元ログ上の行番号とエラー行を表示する。

```text
=== ErrorInsight Result ===

[1] Line 12
Error:
ValueError: invalid literal for int() with base 10: 'abc'
```

エラー行が見つからない場合は、以下のように表示する。

```text
=== ErrorInsight Result ===

エラーが見つかりませんでした。
```

## 有料版への導線

有料版では、抽出したエラー行に対する原因候補表示や、より詳しい調査支援機能を提供する予定。
ただし、具体的な分析内容や内部仕様は Public repository には記載しない。

## 正常系の動き

1. ユーザーがエラーログをクリップボードにコピーする
2. ユーザーがCLIで `errorinsight` を実行する
3. ErrorInsight がクリップボード内の複数行ログを取得する
4. ログを1行ずつ確認する
5. エラーらしいキーワードを含む行を抽出する
6. 抽出結果をコンソールに表示する

## 異常系の動き

### クリップボードが空の場合

- ログが取得できないことを表示する
- 処理を終了する

### エラーらしい行が見つからない場合

- エラー行が見つからなかったことを表示する
- 処理を終了する

### クリップボードの取得に失敗した場合

- クリップボードを読み取れなかったことを表示する
- 処理を終了する

## ユーザー操作の流れ

1. 開発中にエラーが発生する
2. ターミナルやコンソールに表示されたログをコピーする
3. ターミナルで `errorinsight` を実行する
4. 抽出されたエラー行を確認する
5. 表示された行番号とエラー行をもとに、修正箇所を調べる
