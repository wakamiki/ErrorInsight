# Internal Design

## 全体構成

無料版では、CLI起動後に以下の順番で処理する。

1. クリップボードからログ文字列を取得する
2. ログ文字列を行単位に分割する
3. エラーらしい行を抽出する
4. 抽出結果をコンソール表示用に整形する
5. コンソールに表示する

## 責務分離

- CLI制御: 処理全体の流れを管理する
- 入力処理: クリップボードからログ文字列を取得する
- 抽出処理: エラーらしい行を抽出する
- 表示処理: 結果をコンソールに表示しやすい形に整える

## 入力処理

- クリップボードから文字列を取得する
- 取得した文字列が空の場合は、空として扱う
- 入力処理ではエラー判定を行わない

## 抽出処理

- ログ文字列を1行ずつ確認する
- 判定キーワードを含む行をエラー候補として抽出する
- 大文字・小文字の違いは区別しない
- 抽出結果には、元ログ上の行番号とエラー行の文字列を含める
- 抽出処理では原因候補の推測を行わない

## 表示処理

- 抽出結果を外部設計で決めた形式に整形する
- 元ログ上の行番号を表示する
- エラー行がない場合は、見つからなかったことを表示する
- 表示処理では抽出判定を行わない

## データの流れ

1. クリップボードからログ文字列を取得する

```text
clipboard_text: str
```

2. ログ文字列を行単位で扱う

```text
lines: list[str]
```

3. エラー候補行を抽出する

```text
error_lines: list[ErrorLine]
```

各要素は、`ErrorLine` として元ログ上の行番号とエラー行を持つ。

```text
ErrorLine(
  line_number=12,
  text="ValueError: invalid literal for int() with base 10: 'abc'"
)
```

4. 表示用文字列に整形する

```text
output_text: str
```

## 関数設計

### main

CLI起動時の入口。
入力、抽出、表示の流れを呼び出す。

- 入力: なし
- 出力: なし

### get_clipboard_text

クリップボードから文字列を取得する。

- 入力: なし
- 出力: クリップボード内の文字列

### extract_error_lines

ログ文字列からエラーらしい行を抽出する。

- 入力: ログ文字列
- 出力: `list[ErrorLine]`

### ErrorLine

1件のエラー候補行を表すデータ型。

- `line_number`: 元ログ上の行番号
- `text`: 元ログのエラー行文字列

### format_result

抽出結果を表示用文字列に整形する。

- 入力: エラー候補行一覧
- 出力: 表示用文字列

## 有料版との境界

Public repository では、原因候補推測や詳細分析の具体的な処理は扱わない。
有料版で必要になる分析処理は Private repository 側で設計・実装する。

## 将来拡張の余地

- 有料版として原因候補表示を追加する
- Private repository 側で外部AI API連携を検討する
- ファイル入力に対応する
- 言語ごとの切り替え機能を追加する
- エラー件数の集計に対応する
- エラー傾向分析に対応する
- 出力形式を切り替えられるようにする
- 判定キーワードを設定ファイルで変更できるようにする
