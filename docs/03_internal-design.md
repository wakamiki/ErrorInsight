# Internal Design

## 全体構成

v1では、CLI起動後に以下の順番で処理する。

1. クリップボードからログ文字列を取得する
2. ログ文字列を行単位に分割する
3. エラーらしい行を抽出する
4. 抽出したエラー行ごとに原因候補を推測する
5. 抽出結果と原因候補をコンソール表示用に整形する
6. コンソールに表示する

## 責務分離

- CLI制御: 処理全体の流れを管理する
- 入力処理: クリップボードからログ文字列を取得する
- 抽出処理: エラーらしい行を抽出する
- 分析処理: エラー行から原因候補を推測する
- 表示処理: 結果をコンソールに表示しやすい形に整える

## 入力処理

- クリップボードから文字列を取得する
- 取得した文字列が空の場合は、空として扱う
- 入力処理ではエラー判定や原因推測を行わない

## 抽出処理

- ログ文字列を1行ずつ確認する
- 判定キーワードを含む行をエラー候補として抽出する
- 大文字・小文字の違いは区別しない
- 抽出結果には、元ログ上の行番号とエラー行の文字列を含める

## 分析処理

- 抽出したエラー行に含まれる例外名やキーワードから原因候補を返す
- 判断できない場合は「不明」を返す
- 原因候補は断定せず、「可能性がある」という表現にする

## 表示処理

- 抽出結果を外部設計で決めた形式に整形する
- 元ログ上の行番号を表示する
- 原因候補を表示する
- エラー行がない場合は、見つからなかったことを表示する

## データの流れ

1. クリップボードからログ文字列を取得する
```text
clipboard_text: str
```
2. ログ文字列を行単位で扱う
```text
lines: list[str]
```
3. エラー候補行を抽出する
```text
error_lines: list[dict]
```
各要素は、元ログ上の行番号とエラー行を持つ。
```text
{
  "line_number": 12,
  "text": "ValueError: invalid literal for int() with base 10: 'abc'"
}
```
4. エラー候補行ごとに原因候補を付与する
```text
analysis_results: list[dict]
```
各要素は、行番号、エラー行、原因候補を持つ。
```text
{
  "line_number": 12,
  "text": "ValueError: invalid literal for int() with base 10: 'abc'",
  "cause_candidate": "数値に変換できない文字列を int() に渡している可能性があります。"
}
```

5. 表示用文字列に整形する
```text
output_text: str
```


## 関数設計

### main

CLI起動時の入口。
入力、抽出、分析、表示の流れを呼び出す。
- 入力: なし
- 出力: なし

### get_clipboard_text

クリップボードから文字列を取得する。
- 入力: なし
- 出力: クリップボード内の文字列

### extract_error_lines

ログ文字列からエラーらしい行を抽出する。
- 入力: ログ文字列
- 出力: エラー候補行一覧

### analyze_error_line

エラー行から原因候補を推測する。
- 入力: エラー行文字列
- 出力: 原因候補文字列

### format_result

抽出結果と原因候補を表示用文字列に整形する。
- 入力: 分析結果一覧
- 出力: 表示用文字列

## 将来拡張の余地

- 外部AI APIと連携し、より柔軟な原因推測を行う
- ファイル入力に対応する
- 言語ごとの切り替え機能を追加する
- エラー件数の集計に対応する
- エラー傾向分析に対応する
- 出力形式を切り替えられるようにする
- 判定キーワードを設定ファイルで変更できるようにする
