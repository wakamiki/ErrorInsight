# Implementation Plan

## 実装方針

- この Public repository では無料版を実装する
- 無料版完成を `01.00.00` として扱う
- 現在の無料版は `01.00.00` として完成済みとする
- 有料版は `02.00.00` 以降として Private repository で扱う
- 責務分離を学ぶため、処理ごとにファイルを分けて実装する
- まずはクリップボード取得、エラー行抽出、簡易分析、コンソール表示までを実装する
- 最初から複雑なクラス設計にはせず、関数ベースで実装する
- 各ファイルは1つの責務に集中させる
- エラー行から見て取れる範囲の簡易分析は無料版で実装する
- 有料版の複雑な詳細分析機能は Public repository では実装しない
- クリップボード取得には `pyperclip` を使用する
- 日本語ラベルの表示幅調整には `wcwidth` を使用する
- 自動テストには `pytest` を使用する
- CLIフレームワークは無料版では必須にせず、必要になった段階で `Typer` の導入を検討する

## 使用予定ライブラリ

| ライブラリ | 用途 | 採用理由 |
|---|---|---|
| `pyperclip` | クリップボード取得 | 無料版の入力元がクリップボードのため |
| `wcwidth` | 日本語を含む表示幅の計算 | 全角文字と半角文字が混ざるCLI出力でラベル位置を揃えるため |
| `pytest` | 自動テスト | 抽出・表示処理のテスト作成方法を学ぶため |
| `Typer` | CLI作成 | 将来、オプションやヘルプ表示を整えるため |

### 無料版での扱い

- `pyperclip`、`wcwidth`、`pytest` は無料版から使用する
- `Typer` は無料版では保留し、標準的なエントリーポイント設定で `errorinsight` コマンド起動を実現する

## タスク分解

### 1. パッケージ構成の作成

- `errorinsight/` ディレクトリを作成する
- `__init__.py` を作成する
- `__main__.py` を作成する

### 2. CLI起動設定

- `pyproject.toml` を作成する
- `errorinsight` コマンドで起動できるようにする
- 短縮コマンド `ei` でも起動できるようにする
- `errorinsight` 実行時に `cli.main` が呼ばれるようにする

### 3. クリップボード取得

- `clipboard.py` にクリップボード取得処理を実装する
- 取得できた文字列を `cli.py` に返す
- 空の場合の扱いを確認する

### 4. エラー行抽出

- `extractor.py` に `ErrorLine` を定義する
- `extractor.py` に判定キーワードを定義する
- ログ文字列を行単位で確認する
- キーワードを含む行を `list[ErrorLine]` として行番号付きで返す

### 5. 簡易分析処理

- `analyzer.py` に簡易分析処理を実装する
- 抽出済みの `ErrorLine` を受け取る
- ログ全体から言語の特徴を確認し、`language_hint` を作る
- `language_hint` は、言語ごとの特徴をスコア化して判定する
- `log.lower()` は最初に1回だけ作り、言語判定中で何度も小文字化しない
- 言語判定用キーワードは、あらかじめ小文字で管理する
- 強いヒントと弱いヒントを分け、強いヒントは `+5`、弱いヒントは `+1` とする
- 特定の文言の組み合わせがある場合は、組み合わせヒントとして `+3` する
- 最低判定点は `3` とし、最高点が `3` 未満の場合は `不明` にする
- 最高点が同点の場合は、無理に断定せず `不明` にする
- `Java` と `JavaScript` は、文字列の部分一致ではなくスコア辞書の別キーとして扱う
- 言語判定では複雑な正規表現を多用せず、まずは文字列検索を優先する
- 正規表現が必要な場合は、コンパイル済み正規表現を使う
- `language_hint` がある場合は、該当言語の分析ルールを優先して判定する
- `analysis_rule.py` に分析ルール用のデータ型を定義する
- `analysis_rules.py` に言語ごとの分析ルール一覧を定義する
- 代表的な例外名やキーワードに応じて簡易説明を返す
- Python / Java / C# / JavaScript / SQL の代表的なエラーを対象にする
- 具体的なエラーを広いキーワードより先に判定する
- エラー行から見て取れる範囲の原因候補を返す
- よくある確認ポイントを返す
- `AttributeError` など、エラー本文に型名や属性名のヒントが含まれるものは、必要な分析ルールにだけヒント抽出ルールを持たせる
- ヒント抽出は、該当した分析ルールにヒント抽出ルールがある場合だけ実行する
- 判断できない場合は「不明」とする

### 6. 表示処理

- `presenter.py` に表示用文字列の整形処理を実装する
- エラー行、言語種別、簡易説明、原因候補、確認ポイントがある場合の表示を作る
- ヒントがある場合は、確認ポイントとは別にヒント行を表示する
- `wcwidth` を使い、日本語ラベルの表示幅を考慮して開始位置を揃える
- エラー行がない場合の表示を作る

### 7. 自動テスト

- `tests/test_extractor.py` を作成する
- `tests/test_analyzer.py` を作成する
- `tests/test_presenter.py` を作成する
- 入力と出力が明確な処理からテストする

## 動作確認方法

### 無料版

- クリップボードに複数行ログをコピーする
- `errorinsight` を実行する
- エラーらしい行だけが表示されることを確認する
- 元ログ上の行番号が表示されることを確認する
- 簡易説明、原因候補、確認ポイントが表示されることを確認する
- 判断できない場合に「不明」と表示されることを確認する
- 言語ごとの代表的なエラーで、該当言語の分析ルールが優先されることを確認する
- 複数言語で使われる弱いキーワードだけでは、言語を無理に断定しないことを確認する
- 強い言語ヒントが複数あるログでは、スコアが高い言語が優先されることを確認する
- ヒント抽出対象のエラーで、確認ポイントに追加ヒントが表示されることを確認する
- エラー行がない場合に、見つからなかったことが表示されることを確認する
- `pytest` で抽出処理、簡易分析処理、表示処理の自動テストが通ることを確認する

## 注意点

- Public repository では有料版の複雑な詳細分析機能を実装しない
- `cli.py` に抽出ルールを直接書かない
- `extractor.py` は表示用文字列を作らない
- `analyzer.py` はクリップボード取得や表示を行わない
- `analyzer.py` に大量の分析ルールを直接書かない
- ヒント抽出用の正規表現は、必要な分析ルールに紐づけて管理する
- `presenter.py` は `print` せず、表示用文字列を返す
- 変更は小さい単位で行い、動作確認しながら進める
- 有料版の具体的な仕様は `docs/docs-local/pro-feature-scope.md` に退避し、Private repository で扱う


## 配布方針

ErrorInsight 無料版は、初心者でも扱いやすい形での配布を目指す。

配布時は GitHub の開発用構成とは分離し、
配布専用パッケージを作成する。

### 配布予定先

- GitHub Releases
- Vector

### 配布形式

- ZIP配布
- ローカル専用CLIツール
- 外部ネットワーク通信なし
- GitHub構成と配布構成は分離する
- 配布用パッケージを別途作成する

### 配布パッケージ方針

初心者向けの扱いやすさを優先し、
解凍後すぐに起動できる構成を目指す。

### 想定配布構成

ErrorInsight/
├ Start_ErrorInsight.bat
├ README_FIRST.txt
├ python/
├ errorinsight/
├ docs/
│  ├ operation-guide.pdf
│  └ screenshots/
├ sample_logs/
└ licenses/

## Python同梱配布方針

配布版では、初心者向けの扱いやすさを優先し、
Python実行環境を同梱したZIP配布を検討する。

Python本体は再配布可能なライセンスで提供されているため、
ライセンス表記を同梱したうえで利用する。

また、使用ライブラリについても、
必要に応じてライセンス情報を同梱する。
