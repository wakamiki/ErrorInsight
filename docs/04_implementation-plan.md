# Implementation Plan

## 実装方針

- 責務分離を学ぶため、処理ごとにファイルを分けて実装する
- まずは v0.5 として、クリップボード取得、エラー行抽出、コンソール表示までを実装する
- v0.5 が動作確認できてから、v1 の原因候補推測を追加する
- 最初から複雑なクラス設計にはせず、関数ベースで実装する
- 各ファイルは1つの責務に集中させる
- 外部AI API連携はv1では実装せず、ルールベースの原因候補推測を行う
- クリップボード取得には `pyperclip` を使用する
- 自動テストには `pytest` を使用する
- CLIフレームワークは v1 では必須にせず、必要になった段階で `Typer` の導入を検討する

## 使用予定ライブラリ

| ライブラリ | 用途 | 採用理由 |
|---|---|---|
| `pyperclip` | クリップボード取得 | v1の入力元がクリップボードのため |
| `pytest` | 自動テスト | 抽出・分析・表示処理のテスト作成方法を学ぶため |
| `Typer` | CLI作成 | 将来、オプションやヘルプ表示を整えるため |

### v1での扱い

- `pyperclip` と `pytest` は v0.5 から使用する
- `Typer` は v1 では保留し、標準的なエントリーポイント設定で `errorinsight` コマンド起動を実現する

## 実装順序

### v0.5

1. Pythonパッケージ構成を作る
2. `errorinsight` コマンドで起動できる設定を作る
3. クリップボードから文字列を取得する
4. ログ文字列からエラー候補行を抽出する
5. 抽出結果をコンソールに表示する

### v1

1. エラー行ごとの原因候補推測を追加する
2. 原因候補を含めた出力形式に整える
3. エラーなし・原因不明の場合の表示を確認する

## タスク分解

### v0.5

#### 1. パッケージ構成の作成

- `errorinsight/` ディレクトリを作成する
- `__init__.py` を作成する
- `__main__.py` を作成する

#### 2. CLI起動設定

- `pyproject.toml` を作成する
- `errorinsight` コマンドで起動できるようにする
- `errorinsight` 実行時に `cli.main` が呼ばれるようにする

#### 3. クリップボード取得

- `clipboard.py` にクリップボード取得処理を実装する
- 取得できた文字列を `cli.py` に返す
- 空の場合の扱いを確認する

#### 4. エラー行抽出

- `extractor.py` に判定キーワードを定義する
- ログ文字列を行単位で確認する
- キーワードを含む行を行番号付きで返す

#### 5. 表示処理

- `presenter.py` に表示用文字列の整形処理を実装する
- エラー行がある場合の表示を作る
- エラー行がない場合の表示を作る

### v1

#### 1. 原因候補推測

- `analyzer.py` に原因候補推測処理を実装する
- 例外名やキーワードに応じた原因候補を返す
- 判断できない場合は「不明」を返す

#### 2. 分析結果の表示

- `cli.py` で抽出結果と分析結果をつなげる
- `presenter.py` で原因候補を含む表示形式に整える

#### 3. v1動作確認

- 代表的な Python / Java / C# のエラー行で確認する
- エラー行が複数ある場合を確認する
- エラー行がない場合を確認する


## 変更対象ファイル

| ファイル | 責務 |
|---|---|
| `pyproject.toml` | `errorinsight` コマンドとして起動できる設定 |
| `errorinsight/__init__.py` | Pythonパッケージとして扱うためのファイル |
| `errorinsight/__main__.py` | `python -m errorinsight` 実行時の入口 |
| `errorinsight/cli.py` | CLI全体の処理順を制御する |
| `errorinsight/clipboard.py` | クリップボードからログ文字列を取得する |
| `errorinsight/extractor.py` | ログ文字列からエラー候補行を抽出する |
| `errorinsight/analyzer.py` | エラー行から原因候補を推測する |
| `errorinsight/presenter.py` | CLI表示用の文字列を組み立てる |



## 動作確認方法

### v0.5

- クリップボードに複数行ログをコピーする
- `errorinsight` を実行する
- エラーらしい行だけが表示されることを確認する
- 元ログ上の行番号が表示されることを確認する
- エラー行がない場合に、見つからなかったことが表示されることを確認する

### v1

- 抽出したエラー行ごとに原因候補が表示されることを確認する
- 推測できないエラー行では「不明」が表示されることを確認する
- Python / Java / C# の代表的なエラー行で動作を確認する


## 注意点

- v0.5 の段階では原因候補推測を実装しない
- v1 の段階でも外部AI API連携は実装しない
- `cli.py` に抽出ルールや分析ルールを直接書かない
- `extractor.py` は原因候補を推測しない
- `analyzer.py` はログ全体を走査しない
- `presenter.py` は `print` せず、表示用文字列を返す
- 変更は小さい単位で行い、動作確認しながら進める
