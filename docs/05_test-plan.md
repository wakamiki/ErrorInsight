# 05 テスト計画

## テスト目的

ErrorInsight無料版が、ローカル環境で安全に起動し、クリップボード内のエラーログを読み取り、エラー行を抽出し、対象言語を推定したうえで、原因候補と確認ポイントを表示できることを確認する。

---

## テスト対象

- 起動メッセージ表示
- クリップボード取得
- エラー行抽出
- 言語判定
- スコア判定
- 簡易分析
- 結果表示
- unknown判定
- 空入力・通常文入力

---

## テスト対象外

- 有料版機能
- JSON辞書管理
- モード切り替え
- 外部API連携
- GUI
- 配布用PDF
- Windows Defender警告対応

---

## テスト方針

- 自動テストには `pytest` を使用する
- 入力と出力が明確な処理を優先して自動テストする
- クリップボード取得は手動テストで確認し、CLI入口の主要分岐は自動テストでも確認する
- `extractor.py`、`analyzer.py`、`presenter.py`、`language_detector.py` を主な自動テスト対象にする
- 無料版では、エラー行抽出・言語判定・簡易分析・表示整形を重点的に確認する
- 有料版の詳細分析、モード切り替え、JSON辞書読み込みは対象外とする

---

## テスト方法

### 自動テスト

- `pytest` を実行する
- 関数単位で期待する戻り値を確認する

### 手動テスト

- 実際にログをクリップボードへコピーする
- `errorinsight` または `ei` を実行する
- 表示内容を確認する

---

## 完了条件

- 自動テスト32件がすべて成功する
- Python / Java / C# / JavaScript / SQL の代表的なログで言語判定できる
- 強いヒント・弱いヒント・組み合わせヒントによるスコア判定が動作する
- 最高点が最低判定点に満たない場合は「不明」になる
- 同点の場合は無理に言語を断定しない
- 判定できないログは「不明」になる
- 起動時に `動作モード: ローカル実行` / `外部通信: なし` が表示される

---

## 正常系テスト

- クリップボードに複数行ログがある場合、ログを取得できる
- `error` を含む行を抽出できる
- `exception` を含む行を抽出できる
- `traceback` を含む行を抽出できる
- 抽出した行を行番号付きで表示できる
- 抽出したエラー行ごとに簡易説明を表示できる
- 抽出したエラー行ごとに原因候補を表示できる
- 抽出したエラー行ごとに確認ポイントを表示できる
- ログ全体から言語ヒントを判定できる
- 言語ヒントをスコア方式で判定できる
- 強いヒントを `+5` として加点できる
- 弱いヒントを `+1` として加点できる
- 組み合わせヒントを `+3` として加点できる
- 強いヒントと弱いヒントの点数差により、より確度の高い言語を優先できる
- 複数言語で使われる弱いキーワードだけの場合は、無理に言語を断定しない
- 判断できない場合は「不明」と表示できる
- 複数のエラー行がある場合、すべて表示できる

---

## 異常系テスト

- クリップボードが空の場合、ログが取得できないことを表示する
- エラーらしい行がない場合、見つからなかったことを表示する
- クリップボードの読み取りに失敗した場合、読み取れなかったことを表示する
- 通常の日本語文章を入力した場合、「不明」またはエラーなしとして扱える

---

## 境界値テスト

- 1行だけのログを処理できる
- 空行を含むログを処理できる
- 大文字の `ERROR` を抽出できる
- 小文字の `error` を抽出できる
- 長いエラーメッセージを表示できる
- 最大スコアが `0` の場合は「不明」になる
- 最大スコアが `1` または `2` の場合は「不明」になる
- 最大スコアが `3` 以上で、単独最高点の場合は対象言語を返す
- 最大スコアが同点の場合は「不明」になる

---

## 自動テスト対象

### `extractor.py`

- `extract_error_lines`
- `ErrorLine.line_number`
- `ErrorLine.text`
- 大文字・小文字を区別しない抽出

### `language_detector.py`

- `calculate_language_scores`
- `decide_language_hint`
- `detect_language_hint`
- 強いヒント加点
- 弱いヒント加点
- 組み合わせヒント加点
- 最低判定点未満の unknown 判定
- 同点時の unknown 判定
- Java と JavaScript の誤判定防止

### `analyzer.py`

- `analyze_error_line`
- 言語ヒントを使った分析ルール優先
- 代表的な Python / Java / C# / JavaScript / SQL エラーの簡易分析
- 判断できないエラーの unknown 扱い

### `presenter.py`

- `format_startup_message`
- `format_result`
- 行番号、エラー行、簡易説明、原因候補、確認ポイントの表示
- エラー行がない場合のメッセージ表示
- 末尾の不要な改行がないこと

---

## 手動テスト

### 実行手順

1. テスト用ログをクリップボードにコピーする
2. `errorinsight` または `ei` を実行する
3. 表示結果を確認する

### 確認項目

- 起動メッセージが表示される
- エラー行が抽出されている
- 行番号が正しい
- 元ログの大文字・小文字が維持されている
- 言語ヒントが表示される
- 簡易説明、原因候補、確認ポイントが表示される
- 判断できない場合に「不明」と表示される
- エラーがない場合のメッセージが表示される

---

## 自動テストしにくい処理

- 実際のOSクリップボード取得
- CLIコマンドのインストール状態
- 実行環境依存の表示差異

これらは手動テストで確認する。
