# Test Plan

## テスト方針

- 早い段階から自動テストを導入し、Pythonのテスト作成方法を学ぶ
- まずは入力と出力が明確な処理から自動テストを書く
- `extractor.py`、`presenter.py` を優先して自動テスト対象にする
- クリップボード取得やCLI起動は、最初は手動テストで確認する
- 実装とテストを小さい単位で進める
- 無料版ではエラー行抽出と表示整形のテストを作成する
- 自動テストの書き方を学び、後続の機能追加時に確認しやすい状態を作る
- 自動テストには `pytest` を使用する
- 有料版の詳細分析に関するテストは Public repository では扱わない

## 正常系テスト

### 無料版

- クリップボードに複数行ログがある場合、ログを取得できる
- `error` を含む行を抽出できる
- `exception` を含む行を抽出できる
- `traceback` を含む行を抽出できる
- 抽出した行を行番号付きで表示できる
- 複数のエラー行がある場合、すべて表示できる

## 異常系テスト

- クリップボードが空の場合、ログが取得できないことを表示する
- エラーらしい行がない場合、見つからなかったことを表示する
- クリップボードの読み取りに失敗した場合、読み取れなかったことを表示する

## 境界値テスト

- 1行だけのログを処理できる
- 空行を含むログを処理できる
- 大文字の `ERROR` を抽出できる
- 小文字の `error` を抽出できる
- 長いエラーメッセージを表示できる

## 手動テスト

### 実行手順

1. テスト用ログをクリップボードにコピーする
2. `errorinsight` または `ei` を実行する
3. 表示結果を確認する

### 確認すること

- エラー行が抽出されているか
- 行番号が正しいか
- 元ログの大文字・小文字が維持されているか
- エラーがない場合のメッセージが表示されるか

## 自動テスト

### 使用するテストツール

- `pytest`

### テストファイル候補

- `tests/test_extractor.py`
- `tests/test_presenter.py`

### 無料版で対象にする処理

- `extract_error_lines`
- `format_result`

### `extract_error_lines` で確認すること

- 返り値が `list[ErrorLine]` であること
- `ErrorLine.line_number` に元ログ上の行番号が入ること
- `ErrorLine.text` に小文字化前の元の行文字列が入ること
- 大文字・小文字を区別せずに判定できること

### 自動テストしにくい処理

- クリップボード取得
- CLIコマンドのインストール状態

これらはまず手動テストで確認する。

## 有料版テストについて

有料版の原因候補表示、詳細分析、課金、ライセンス認証に関するテストは Private repository 側で扱う。
Public repository には、有料版の具体的なテストケースを含めない。
